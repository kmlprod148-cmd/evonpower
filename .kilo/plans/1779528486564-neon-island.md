# CSMS Architecture Plan: Production-Grade OCPP 1.6J Implementation

## Executive Summary

This plan defines a robust, fault-tolerant backend architecture for a Charging Station Management System (CSMS) using Laravel and OCPP 1.6J. The architecture treats the charger as "eventually consistent" and implements a workflow engine pattern with distinct stages for user intent, command intent, and charger acknowledgments.

---

## 1. Multi-Layered State Machine Design

### 1.1 Reservation States (Business Layer)

```
PENDING → PENDING_CONFIRMATION → APPROVED → RESERVED → SESSION_INITIATED → ACTIVE → COMPLETED/CANCELED
    │              │                │            │               │           │         │
    │              │                │            │               │           │         └─── EXPIRED (hybrid duration)
    │              │                │            │               │           └─── TIMEOUT_NO_TRANSACTION
    │              │                │            │               └─── REMOTE_START_ACCEPTED (waiting for StartTransaction)
    │              │                │            └─── ReserveNow ACK received
    │              │                └─── Payment validated or auto-approved
    │              └─── Payment initiated
    └─ User created reservation
```

### 1.2 Session States (Business Layer)

```
PENDING → INITIATING → IN_PROGRESS → COMPLETED
    │          │              │            │
    │          │              │            └─── NORMAL, TIMEOUT, USER_CANCELLED, CHARGER_ERROR
    │          │              └─── StopTransaction received
    │          └─── RemoteStart accepted, waiting StartTransaction
    └─── Reservation approved
```

### 1.3 Connector States (OCPP Layer - Driven by StatusNotification)

```
Available ↔ Preparing ↔ Charging ↔ Finishing
     ↖                                    ↙
       ↘                               ↙
         Reserved (via ReserveNow)
           ↓
      SuspendedEV/ SuspendedEVSE (during charging)
           ↓
       Unavailable (maintained/offline)
           ↓
          Faulted (error state)
```

### 1.4 State Transition Matrix

| From State | Event | To State | Conditions |
|------------|-------|----------|------------|
| PENDING | payment_confirmed | PENDING_CONFIRMATION | payment_status = PAID |
| PENDING_CONFIRMATION | auto_approve | APPROVED | wallet_debited OR admin_approved |
| APPROVED | reservation_expires | CANCELED | now > expires_at |
| APPROVED | remote_start_sent | RESERVED | command_outbox status = accepted |
| RESERVED | no_start_transaction | CANCELED | timeout > 30s from start_sent |
| RESERVED | start_transaction_recv | SESSION_INITIATED | transaction_id matches reservation |
| SESSION_INITIATED | meter_values_flowing | IN_PROGRESS | first MeterValues received |
| IN_PROGRESS | reservation_expires | COMPLETED | now >= reservation.expires_at |
| IN_PROGRESS | stop_transaction | COMPLETED | transaction stopped |

## 2. Dual-Layer Reservation System

### 2.1 Business-Level Reservation (Laravel)

The `Reservation` model tracks business intent with these key fields:

```php
// Key reservation fields for OCPP integration
'connector_id' => int,        // OCPP connector number (1, 2, etc.)
'ocpp_tag_id' => int|null,    // Tag for authentication
'expires_at' => Carbon,       // HYBRID DURATION: charging stops here regardless of start time
'reservation_id' => int|null, // OCPP reservation ID (assigned by charger)
'status' => ReservationStatus, // Business state machine
'session_initiation_status' => enum('pending','sent','acknowledged','transaction_received','timeout'),
```

### 2.2 Charger-Level Reservation (OCPP ReserveNow)

```
Laravel Reservation (APPROVED) 
    → OcppCommandOutbox 
    → ReserveNow to Charger
    → Charger reserves connector
    → Reservation status = RESERVED
    → remote_start_sent_at timestamp
```

### 2.3 Hybrid Duration Rule

**Critical Rule**: Charging must stop at `reservation.expires_at` regardless of when `RemoteStartTransaction` was accepted.

Implementation:
```php
// In ChargingSessionManager::checkAndStopExpiredSessions()
if ($session->started_at && $reservation->expires_at < now()) {
    $this->stopChargingSession($session, 'reservation_expired');
}
```

## 3. OCPP Communication & Reliability

### 3.1 Command Outbox Pattern

```php

Schema::create('ocpp_command_outbox', function (Blueprint $table) {
    $table->id();

    $table->string('charge_box_id');

    $table->timestamp('sent_at')->nullable();
    $table->timestamp('acknowledged_at')->nullable();
    $table->timestamp('responded_at')->nullable();
    $table->json('response')->nullable();
    $table->integer('retry_count')->default(0);
    $table->integer('max_retries')->default(3);
    $table->timestamp('next_retry_at')->nullable();
    $table->timestamps();
    
    $table->index(['charge_box_id', 'status']);
    $table->index(['reservation_id', 'command']);
    $table->index(['correlation_id']);

```

### 3.2 Outbox Service Implementation

```php
class OcppCommandOutboxService
{
    public function enqueue(array $command): OcppCommandOutbox
    {
        return OcppCommandOutbox::create([
            'command' => $command['name'],
            'charge_box_id' => $command['chargeBoxId'],
            'connector_id' => $command['connectorId'] ?? null,
            'payload' => $command['payload'],
            'status' => 'pending',
            'correlation_id' => $this->generateCorrelationId($command),
        ]);
    }
    
    public function processPending(): void
    {
        OcppCommandOutbox::where('status', 'pending')
            ->where(function($q) {
                $q->whereNull('next_retry_at')
                  ->orWhere('next_retry_at', '<=', now());
            })
            ->chunk(100, function($commands) {
                foreach ($commands as $command) {
                    SendOcppCommandJob::dispatch($command);
                }
            });
    }
    
    private function generateCorrelationId(array $command): string
    {
        // Ensures idempotency: same command won't be sent twice
        return md5($command['name'] . $command['chargeBoxId'] . json_encode($command['payload']));
    }
}
```

```php
    $table->index(['received_at']);

class OcppEventIngestionService
{
    public function ingest(string $messageType, string $chargeBoxId, array $payload): void
    {
        $event = OcppIncomingEvent::create([
            'message_type' => $messageType,
            'charge_box_id' => $chargeBoxId,
            'connector_id' => $payload['connectorId'] ?? null,
            'payload' => $payload,
            'received_at' => now(),
        ]);
        
        // Dispatch to async processor based on message type
        match($messageType) {
            'StartTransaction' => ProcessStartTransactionJob::dispatch($event),
            'StopTransaction' => ProcessStopTransactionJob::dispatch($event),
            'StatusNotification' => ProcessStatusNotificationJob::dispatch($event),
        };
    }
}
```

### 3.4 Strict Correlation Logic for StartTransaction

```php
class StartTransactionCorrelator
{
    public function findMatchingReservation(array $payload): ?Reservation
    {
        $chargeBoxId = $payload['chargeBoxId'] ?? $payload['charge_point_id'];
        $connectorId = $payload['connectorId'];
        $idTag = $payload['idTag'];
        $timestamp = Carbon::parse($payload['timestamp']);
        
        // Find active reservations matching criteria
        return Reservation::where('charging_point_id', function($q) use ($chargeBoxId) {
                $q->select('id')->from('charging_points')
                  ->where('charge_box_id', $chargeBoxId)
                  ->limit(1);
            })
            ->where('connector_id', $connectorId)
            ->where('status', 'RESERVED')
            ->where('ocpp_tag_id', function($q) use ($idTag) {
                $q->select('id')->from('ocpp_tags')->where('tag', $idTag)->limit(1);
            })
            ->where(function($q) use ($timestamp) {
                // Reservation must encompass this timestamp
                $q->where('start_time', '<=', $timestamp)
                  ->where('expires_at', '>=', $timestamp);
            })
            ->whereNull('transaction_id') // Not already matched
            ->first();
    }
}
```

## 4. Error Handling & Edge Cases

### 4.1 Failure Matrix: Command Accepted but No Transaction Received

| Command | Scenario | Timeout | Action | User Visible? |
|---------|----------|---------|--------|---------------|
| RemoteStartTransaction | Accepted, no StartTransaction in 30s | 30s | Mark session as TIMEOUT, CANCEL reservation | Yes - Error message |
| RemoteStartTransaction | Accepted, transaction for different connector | Immediate | Reject, log mismatch | No - OCPP spec violation |
| ReserveNow | Accepted, no status confirmation | 10s | Retry with backoff x3 | No - Background |
| StopTransaction | Failed | Immediate | Alert operator, manual intervention | No - Operational |
| UnlockConnector | Failed (offline charger) | Immediate | Queue for when online | No - Operational |

### 4.3 Offline Charger Handling

```php
class OfflineChargerHandler
{
    // Start phase - user visible errors
    public function handleStartFailure(Reservation $reservation, string $error): void
    {
        // Set reservation status to FAILED
        $reservation->update([
            'status' => 'FAILED',
            'last_error' => $error,
            'last_error_at' => now(),
        ]);
        
        // Notify user immediately
        Notification::notify($reservation->user, 'charging_start_failed', [
            'message' => 'Unable to start charging. Charger is offline.',
            'reservation_id' => $reservation->id,
        ]);
    }
    
    // Stop phase - operational alerts
    public function handleStopFailure(ChargingSession $session, string $error): void
    {
        // Create alert for operator
        Alert::create([
            'type' => 'stop_failure',
            'charging_session_id' => $session->id,
            'message' => "Failed to stop session: {$error}",
            'severity' => 'warning',
        ]);
        
        // Queue for retry when charger comes online
        RetryStopTransactionJob::dispatch($session)
            ->delay(now()->addMinutes(5));
    }
}
```

### 5.2 Locking Strategy for State Transitions

```php
class ReservationService
{
    public function transitionToReserved(Reservation $reservation): bool
    {
        return DB::transaction(function() use ($reservation) {
            // Lock the reservation row for update
            $reservation = Reservation::where('id', $reservation->id)
                ->lockForUpdate()
                ->firstOrFail();
            
            // Verify current state allows transition
            if ($reservation->status !== 'APPROVED') {
                throw new InvalidStateException('Cannot transition from ' . $reservation->status);
            }
            
            // Perform transition
            $reservation->update([
                'status' => 'RESERVED',
                'remote_start_sent_at' => now(),
            ]);
            
            return true;
        }, 5); // 5 second lock timeout
    }
}
```

### 5.3 Reconciliation Service

```php
class ChargingSessionReconciliationService
{
    /**
     * Scheduled task to detect and resolve discrepancies
     * Run every 5 minutes via scheduler
     */
    public function reconcile(): ReconciliationReport
    {
        $report = new ReconciliationReport();
        
        // Discrepancy 1: Session marked active but connector says Available
        $discrepancies = ChargingSession::where('status', 'IN_PROGRESS')
            ->whereHas('chargingPoint.connectors', function($q) {
                $q->where('status', 'Available');
            })
            ->get();
        
        foreach ($discrepancies as $session) {
            $this->resolveSessionConnectorMismatch($session);
            $report->addResolved('session', $session->id, 'connector_status_mismatch');
        }
        
        // Discrepancy 2: Reservation expired but session still active
        Reservation::where('status', 'ACTIVE')
            ->where('expires_at', '<', now())
            ->with('chargingSession')
            ->get()
            ->each(function($reservation) use ($report) {
                if ($reservation->chargingSession && $reservation->chargingSession->isActive()) {
                    $this->stopSession($reservation->chargingSession, 'reservation_expired');
                    $report->addResolved('reservation', $reservation->id, 'expired_session_stopped');
                }
            });
        
        // Discrepancy 3: Connector Reserved but no reservation exists
        Connector::where('status', 'Reserved')
            ->whereDoesntHave('reservations', function($q) {
                $q->whereIn('status', ['RESERVED', 'ACTIVE']);
            })
            ->get()
            ->each(function($connector) {
                $connector->update(['status' => 'Available']);
            });
        
        return $report;
    }
    
    private function resolveSessionConnectorMismatch(ChargingSession $session): void
    {
        // Log the discrepancy
        Log::warning('Session-Connector mismatch detected', [
            'session_id' => $session->id,
            'charging_point_id' => $session->charging_point_id,
        ]);
        
        // Attempt to stop the session gracefully
        try {
            $this->stopSession($session, 'reconciliation_stop');
        } catch (Exception $e) {
            // Create alert for manual intervention
            Alert::create([
                'type' => 'manual_intervention_required',
                'reference_id' => $session->id,
                'message' => "Session {$session->id} requires manual stop: " . $e->getMessage(),
            ]);
        }
    }
}
```

### 6.2 Background Jobs Required

| Job | Purpose | Queue | Retry Policy |
|-----|---------|-------|--------------|
| `SendOcppCommandJob` | Send command to charger | ocpp-outbound | 3 retries, exponential backoff |
| `ProcessStartTransactionJob` | Correlate StartTransaction | ocpp-inbound | No retry (idempotent) |
| `ProcessStopTransactionJob` | Process StopTransaction | ocpp-inbound | No retry |
| `ProcessStatusNotificationJob` | Update connector status | ocpp-inbound | No retry |
| `ProcessReservationExpirationJob` | Handle expired reservations | default | No retry |
| `ChargingSessionTimeoutJob` | Timeout waiting for StartTransaction | ocpp-timeout | No retry |
| `ChargingSessionReconciliationJob` | Scheduled reconciliation | default | No retry |
| `RetryStopTransactionJob` | Retry failed stop commands | ocpp-retry | 5 retries |
| `AlertOnChargerOfflineJob` | Alert operators for persistent offline | alerts | No retry |

## 8. Key Design Principles Applied

1. **Eventually Consistent**: Laravel state ≠ Charger state; reconciliation bridges gap
2. **Idempotency**: All commands use correlation IDs; duplicate processing safe
3. **Audit Trail**: Every state transition logged with timestamp and actor
4. **Separation of Concerns**: Business logic separate from OCPP protocol logic
5. **Graceful Degradation**: System works even when charger offline
6. **Observable**: Comprehensive logging and metrics for operational visibility
